# 한국어 커밋 메시지와 PR 설명

먼저 `git log --oneline -20`으로 저장소의 기존 형식을 봐요. 이미 정해진 형식(Conventional Commits 접두어, 이슈 번호 위치 등)이 있으면 그것을 따르고, 아래는 정해진 것이 없을 때의 기본이에요.

## 커밋 제목

- 50자 안쪽, 한 줄. 끝에 마침표를 찍지 않아요.
- **무엇을 바꿨는지**를 명사형으로 끝내요: "로그인 실패 시 재시도 버튼 추가", "설정 파일 경로 오류 수정".
- 자주 쓰는 끝말: 추가, 수정, 삭제, 변경, 개선, 정리, 분리, 이름 변경.
- 접두어를 쓰는 저장소라면 영어 접두어 뒤에 한국어: `fix: 설정 파일 경로 오류 수정`.

## 커밋 본문

- 제목과 한 줄 띄우고, **왜** 바꿨는지를 써요. 무엇을 바꿨는지는 diff가 보여 줘요.
- 한 줄 72자 안쪽에서 줄을 바꿔요.
- 문장은 "~했어요" 또는 "~함" 중 저장소에서 쓰는 쪽으로 맞춰요. 섞지 마세요.
- 관련 이슈는 마지막 줄에: `Closes #123`.

예:

```
업로드 중 연결이 끊기면 처음부터 다시 받던 문제 수정

청크 번호를 저장하지 않아서 재연결할 때마다 0번부터 보냈어요.
마지막으로 성공한 청크를 기억해 두고 그다음부터 이어 보내요.

Closes #412
```

## PR 설명

다음 순서로 쓰고, 해당 없는 칸은 빼요.

1. **요약**: 무엇이 달라지는지 한두 문장
2. **이유**: 어떤 문제를 푸는지, 관련 이슈
3. **변경 내용**: 리뷰어가 볼 곳을 짧은 목록으로
4. **확인 방법**: 실행한 테스트와 결과, 직접 확인한 화면이나 명령
5. **주의할 점**: 마이그레이션, 설정 변경, 되돌리는 방법, 아직 확인하지 못한 것

확인하지 못한 것은 확인했다고 쓰지 말고 그대로 적어요.
