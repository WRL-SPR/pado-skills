# 한국어 UI 문구와 문서

사용자가 읽는 한국어(버튼, 안내, 오류 메시지, 설정 설명, README)를 쓰거나 고칠 때 따르세요.

## 말투

- 기본은 **해요체**예요. "~합니다"와 섞지 마세요. 한 화면 안에서는 말투를 하나로 맞춰요.
- 사용자를 "당신", "귀하"로 부르지 마세요. 주어를 빼도 자연스러우면 빼요.
- 명령보다 안내로 써요. "입력하십시오" 대신 "입력해 주세요".

## 짧고 구체적으로

- 한 문장에 한 가지만 말해요. 40자를 넘으면 나눌 수 있는지 봐요.
- 무엇이 일어났는지, 사용자가 무엇을 하면 되는지를 써요. 원인 코드나 내부 이름은 꼭 필요할 때만 덧붙여요.
  - 나쁨: "오류가 발생했습니다(ERR_42)."
  - 좋음: "파일을 저장하지 못했어요. 디스크 공간을 확인해 주세요."

## 번역투 피하기

| 피할 표현 | 바꿀 표현 |
|---|---|
| ~에 대해 확인하세요 | ~을 확인해 주세요 |
| ~를 가지고 있어요 | ~가 있어요 |
| ~되어집니다 | ~돼요 |
| ~하는 것이 가능해요 | ~할 수 있어요 |
| 성공적으로 저장되었습니다 | 저장했어요 |
| ~의 ~의 ~ | 조사를 줄이거나 문장을 나눠요 |

## 버튼과 메뉴

- 버튼은 동작을 짧게: "저장", "다시 시도", "지우기". "확인"만 쓰기보다 무엇을 확인하는지 드러내요.
- 되돌릴 수 없는 동작은 결과를 말해요: "영구 삭제", "모두 지우기".
- 메뉴와 제목은 명사형으로 끝내요: "설정", "최근 파일".

## 표기

- 띄어쓰기는 국립국어원 기준을 따르되, 화면에서 굳은 용어(로그인, 다운로드)는 외래어 표기법대로 써요.
- 숫자와 단위는 붙여 써요: 10MB, 3초. 큰 수는 쉼표: 12,000개.
- 날짜는 "2026년 11월 8일" 또는 "11월 8일(일)". 시간은 "오후 3:20".
- 영어 제품명과 코드는 원문 그대로 두고, 조사는 발음에 맞춰요: "GitHub에", "npm을".

## 점검 순서

1. 말투가 한 가지인지
2. 사용자가 다음에 할 일이 보이는지
3. 번역투와 중복 조사가 없는지
4. 버튼 문구가 동작을 말하는지
5. 숫자, 단위, 고유명사 표기가 맞는지
