# 한국어 코드 리뷰

## 먼저 읽기

- diff만 보지 말고, 바뀐 함수를 부르는 곳과 바뀐 함수가 부르는 곳까지 읽어요.
- 테스트가 있으면 무엇을 확인하는지, 빠진 경우가 무엇인지 봐요.

## 무엇을 찾나

1. **정확성**: 잘못된 결과, 빠진 분기, 경계값(빈 값, 0, 아주 큰 값), 동시성
2. **안전**: 입력 검증, 권한 확인, 비밀값 노출, 경로·명령 주입
3. **실패 처리**: 오류를 삼키는 곳, 사용자에게 보이는 메시지, 재시도와 정리
4. **성능**: 반복 안의 I/O, 불필요한 전체 읽기, 커지는 메모리
5. **단순함**: 쓰이지 않는 코드, 중복, 필요 이상으로 일반화된 구조

## 쓰는 법

각 지적은 이 모양으로 써요.

```
[필수] 파일:줄 — 한 줄 요약
어떤 입력이나 상태에서 → 무엇이 잘못되는지
고치는 방향 (코드는 필요할 때만 짧게)
```

- **[필수]**: 합치기 전에 고쳐야 하는 것. 실제로 틀리거나 위험한 것만.
- **[권장]**: 고치면 좋지만 막을 정도는 아닌 것.
- **[참고]**: 질문, 취향, 나중에 할 일.

## 어조

- 사람이 아니라 코드를 말해요. "왜 이렇게 했어요?" 대신 "이 경우 X가 돼요".
- 추측은 추측이라고 써요: "확인하지 못했지만, ~일 수 있어요".
- 잘된 점이 분명하면 한 줄로 짚어요. 칭찬을 억지로 만들지는 마세요.

## 마무리

맨 끝에 요약 한 단락: 필수 몇 개, 권장 몇 개, 합쳐도 되는지에 대한 의견. 직접 실행해 보지 않았다면 그렇다고 써요.
