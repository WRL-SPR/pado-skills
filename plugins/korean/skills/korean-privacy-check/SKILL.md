# 한국 개인정보 코드 점검

한국 사용자의 개인정보를 다루는 코드를 볼 때 쓰는 점검표예요. 법률 자문이 아니에요. 법적 판단이 필요하면 담당자나 전문가에게 확인하라고 안내하세요.

## 1. 어떤 정보가 있는지 찾기

코드, 스키마, 로그 형식, API 응답에서 다음을 찾아요.

| 종류 | 예 | 찾는 단서 |
|---|---|---|
| 고유식별정보 | 주민등록번호, 외국인등록번호, 여권번호, 운전면허번호 | `rrn`, `jumin`, `ssn`, 6자리-7자리 숫자 패턴 |
| 연락처 | 휴대폰 번호, 이메일, 주소 | `phone`, `mobile`, `010` |
| 금융 | 계좌번호, 카드번호 | `account`, `card`, 14~16자리 숫자 |
| 민감정보 | 건강, 장애, 정치 성향, 종교 | 진료, 질병, 장애 관련 필드 |
| 위치 | 정밀 위치, 이동 기록 | `lat`, `lng`, GPS 기록 |

## 2. 점검 항목

- **수집 최소화**: 기능에 꼭 필요한 항목만 받는지. 주민등록번호는 법에서 허용한 경우가 아니면 받지 않아요. 본인 확인은 휴대폰 본인인증이나 아이핀 같은 대체 수단을 쓰는지 봐요.
- **저장 시 암호화**: 고유식별정보, 비밀번호, 계좌·카드번호가 평문으로 저장되지 않는지. 비밀번호는 복호화할 수 없는 해시(bcrypt, scrypt, Argon2)로 저장하는지.
- **로그와 오류 메시지**: 요청 본문, 쿼리, 예외 메시지에 개인정보가 그대로 남지 않는지. 남는다면 가림 처리하는지.
- **화면 표시 가림**: 목록이나 알림에서 일부만 보이는지. 예: 010-****-1234, 홍*동, 123456-1******.
- **전송**: 외부 API, 분석 도구, 오류 수집 서비스로 개인정보가 나가지 않는지. 나간다면 그 목적이 분명한지.
- **보관 기간과 파기**: 탈퇴나 목적 달성 후 지우는 코드나 작업이 있는지.
- **접근 통제**: 관리자 화면과 내보내기 기능에 권한 확인과 접근 기록이 있는지.

## 3. 결과 쓰기

찾은 문제마다 위치(파일:줄), 어떤 정보가 어디로 새는지, 고치는 방향을 써요. 확실하지 않은 것은 "확인 필요"로 따로 모아요.
